# macOS (Emacs) style — 既知の制限

- **範囲選択はテーブルセルの境界で止まります:** Shift+Ctrl+P/N/B/F/A/Eは、プレーンテキスト内や単一のテーブルセル内では通常通り選択範囲を拡張します。セルの境界では、隣接セルへ踏み込むこともなく（素のCtrl+B/Fとは異なります）、セルをまたいで選択を拡張することもありません（Shift+矢印キーとは異なります）。セルをまたぐ選択にはShift+矢印キーを使ってください。

- **Live PreviewでUPして高さのある折り返しセルに入ると一瞬スクロールする:** 画面の高さを超える折り返しコンテンツを持つセルにUPで入ると、一瞬だけセルの先頭までスクロールしてから、一番下の表示行にジャンプします。これは、ObsidianのLive Previewテーブルウィジェット内で一番下の表示行を特定するために使っている、2段階のナビゲーションに固有の副作用です。

- **複数セルにまたがるカット・コピー・貼り付けは非対応（Kill Line / Kill Region / Copy Region / Yank）:** Kill Line、Kill Region、Copy Region、Yankはテキストレベルの操作であり、テーブル内では個々のセルのテキスト内容に対して動作します。複数セルを選択してこれらのコマンドでカット・コピー・貼り付けを試みることはサポートされていません。複数セルにまたがるカット・コピー・貼り付けには、右クリックのコンテキストメニューを使ってください。

- **ソースモードでのテーブル検出はヒューリスティックです:** ソースモードでは、テーブルの行は単純な文字列チェック（行が`|`で始まり`|`で終わるか）によって識別されます。構文木を使うLive Previewモードとは異なり、この方法では、たまたまこのパターンに一致するもののMarkdownテーブルの一部ではない行で、予期しない挙動が起きることがあります。

- **プレーンテキストからテーブルに入ると常に一番左のセルに入ります:** プレーンテキストの行からCursor UP/DOWNで隣接するテーブル行に移動すると、常にその行の一番左のセルに入ります。これはVim自身の`gj`/`gk`と同じ挙動です — Obsidian のLive Previewテーブルウィジェットは、フォーカスされていないテーブル行について、外側のエディタに文字単位の位置情報を一切提供しないため、着地する前にどの列に対応するセルかを判断する方法がありません。そのセル*内*の列位置は、テーブル内の行間移動と同様に保持されます。

- **ショートカットの競合**
  - **Windows — OSレベルのショートカットは検出されません:** Ctrl+A（HOME）とCtrl+Y（Yank）は、それぞれシステムのSelect allとRedoのショートカットを上書きします。これらはObsidianのホットキーではなくOSレベルのデフォルトであるため、Hotkey settingsはこの競合を検出できず、利用可能と表示してしまいます。同梱の **Select all** と **Redo** コマンドを代替として使用できます — コマンドパレットから実行するか、それぞれに独自のホットキーを割り当ててください。
  - **Page down / Page up — 貼り付けとの競合:** Ctrl+V（Windows）またはCmd+V（macOS）をPage downまたはPage upに割り当てると、エディタ以外のプラグインビュー（例: Excalidraw）でのキーボードによる貼り付けが壊れます。Yank（Ctrl+Y）はMarkdownエディタ内での貼り付けを復元しますが、それらのビューでのCmd+Vの代わりにはなりません。右クリック → ペーストは回避策として引き続き利用できます。これらのコマンドには、貼り付けと競合しないキーを割り当てることを推奨します。
