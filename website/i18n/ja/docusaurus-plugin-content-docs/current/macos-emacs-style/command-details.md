# macOS (Emacs) style — コマンド詳細

注: (*) はLive Previewモード固有の挙動を示します。

<details>
<summary>Cursor UP</summary>

- **テキスト内:** 直前の表示行へ移動します。物理的なカーソルキーと同じ挙動です。
- **コールアウト・画像・埋め込み・水平線の下（Live Preview）(\*):** そのブロックに入り、Markdownのソースを展開します。物理的なカーソルキーの挙動と一致します。コールアウトの場合、カーソルはその直下の空行にある必要があります。画像・埋め込み（`![[...]]`、`![...](...)`）の場合、その記法が行頭から始まっている場合に適用されます。水平線（`---`、`***`、`___`）の場合、カーソルはその行の先頭に着地します。
- **テーブルの下（\*):** カーソルがテーブルのすぐ下の行にある場合、テーブルに入り、右下セルの一番下の表示行の左端に移動します。
- **テーブルセル内（\*):**
  - **最初の表示行にいる場合:** 同じ列の直上のセルの、一番下の表示行の左端に移動します。折り返されていないセルの場合、これはセルの先頭になります。
  - **それ以外の表示行にいる場合:** 同じセル内で1つ上の表示行に移動します。物理的なカーソルキーと同じ挙動です。
- **テーブルから上に抜け出す場合（\*):** テーブルの一番上の行にいる場合、テーブルから抜け出して上の行に移動します。

</details>

<details>
<summary>Cursor DOWN</summary>

- **テキスト内:** 1つ下の表示行へ移動します。物理的なカーソルキーと同じ挙動です。
- **コールアウト・画像・埋め込み・水平線の上（Live Preview）(\*):** そのブロックに入り、Markdownのソースを展開します。物理的なカーソルキーの挙動と一致します。コールアウトの場合、次の行がコールアウトのヘッダー（`> [!type]...`）である必要があります。画像・埋め込み（`![[...]]`、`![...](...)`）の場合、その記法が行頭から始まっている場合に適用されます。水平線（`---`、`***`、`___`）の場合、カーソルはその行の先頭に着地します。
- **テーブルの上（\*):** カーソルがテーブルのすぐ上の行にある場合、テーブルに入り、左上セルの先頭に移動します。
- **テーブルセル内（\*):**
  - **それ以外の表示行にいる場合:** 同じセル内で1つ下の表示行に移動します。物理的なカーソルキーと同じ挙動です。
  - **最後の表示行にいる場合:** 同じ列の、下の行にあるセルの先頭にジャンプします。
- **テーブルから下に抜け出す場合（\*):** 最後の行にあるいずれかのセルの最後の表示行から、テーブルの外へ出て下の行の先頭に移動します。

</details>

<details>
<summary>Cursor LEFT</summary>

- **テキスト内:** 1文字左に移動します。物理的なカーソルキーと同じ挙動です。
- **テーブルの下、行の先頭にいる場合（\*):** テーブルに入り、右下セルの内容の末尾（一番下の表示行）に移動します。
- **テーブルセル内（\*):** セルの内容の中で1文字左に移動します。
- **セル内容の先頭にいる場合（\*):** 同じ行の左隣のセルのテキスト末尾にジャンプします。
- **一番左のセルの先頭にいる場合（データ行）(\*):** 上の行の一番右のセルの末尾にジャンプします。（→ **Cross-Row Navigation** 設定）
- **一番左のセルの先頭にいる場合（ヘッダー行）(\*):** テーブルから抜け出して上の行に移動します。（→ **Cross-Row Navigation** 設定）

</details>

<details>
<summary>Cursor RIGHT</summary>

- **テキスト内:** 1文字右に移動します。物理的なカーソルキーと同じ挙動です。
- **テーブルの上、行の末尾にいる場合（\*):** テーブルに入り、左上セルの先頭に移動します。
- **テーブルセル内（\*):** セルの内容の中で1文字右に移動します。
- **セル内容の末尾にいる場合（\*):** 同じ行の右隣のセルのテキスト先頭にジャンプします。
- **一番右のセルの末尾にいる場合（最終行以外）(\*):** 下の行の一番左のセルの先頭にジャンプします。（→ **Cross-Row Navigation** 設定）
- **一番右のセルの末尾にいる場合（最終行）(\*):** テーブルから抜け出して下の行に移動します。（→ **Cross-Row Navigation** 設定）

</details>

<details>
<summary>Cursor HOME</summary>

- 行の先頭に向かって、最大3段階で移動します。
  - **ステップ1:** 現在の表示行の左端に移動します（行が折り返されていて、カーソルが最初の表示行にない場合）。（→ **Visual Line Movement** 設定）
  - **ステップ2:** Markdownの記法 — インデント、リストマーカー（`- `、`* `、`+ `）、チェックボックス（`- [ ] `）、番号付きリスト（`1. `または`1) `）、引用（`>`） — を飛び越えて本文の先頭に移動します。Smart home (advanced) がONの場合、見出しマーカー（`# `）、脚注（`[^1]: `）、コールアウトの種類マーカー（`[!type]`）も飛び越します。（→ **Smart home** 設定）
  - **ステップ3:** 行の先頭に移動します。
- **テーブルセル内では**、さらに1段階が加わります:
  - セル内の最初以外の行（`<br>`の後）の先頭にいる場合: それ以上は移動しません。
  - 同じ行の左隣のセルのテキスト末尾にジャンプします。
  - 一番左の列にいる場合: 上の行の一番右のセルにジャンプします。（→ **Cross-Row Navigation** 設定）
  - ヘッダー行の一番左のセルにいる場合: テーブルから抜け出して上の行に移動します。

</details>

<details>
<summary>Cursor END</summary>

- 行の末尾に向かって、最大2段階で移動します。
  - **ステップ1:** 現在の表示行の右端に移動します（行が折り返されていて、カーソルが最後の表示行にない場合）。（→ **Visual Line Movement** 設定）
  - **ステップ2:** 行の末尾に移動します。
- **テーブルセル内では**、さらに1段階が加わります:
  - セル内の最後以外の行（`<br>`の前）の右端にいる場合: それ以上は移動しません。
  - 同じ行の右隣のセルのテキスト先頭にジャンプします。
  - 一番右の列にいる場合: 下の行の一番左のセルにジャンプします。（→ **Cross-Row Navigation** 設定）
  - 最終行の一番右のセルにいる場合: テーブルから抜け出して下の行に移動します。
- **テーブルセル内（ソースモード）:**
  - **カーソルが`<br>`タグの中にある場合:** `<br>`タグを飛び越えて、次のセル内行の右端にジャンプします。
  - **カーソルが最初の`|`より前にある場合（ch=0）:** 最初のセルの本文の先頭にスナップします。

</details>

<details>
<summary>Cursor TOP / Cursor BOTTOM</summary>

- ドキュメントの本当の先頭（TOP）または末尾（BOTTOM） — 現在の行ではなくバッファ自体の端にジャンプします。そのため、Cursor HOME/ENDとは異なり、Smart Homeは適用されず、先頭・末尾の空白もスキップしません。
- **テーブル対応（\*):** ジャンプ先の行自体がテーブルの行だった場合、生のMarkdownテキストの上ではなく、セルの内容の中に着地します — TOPは**一番左**のセル（描画されたセルの中に「それより前」という位置は存在しないため）、BOTTOMは**一番右**のセルの末尾（その行の本当の末尾）に着地します。これがないと、テーブルで始まるノートはTOPへジャンプした際に最初の行ではなく*最後*の行に、テーブルで終わるノートはBOTTOMへジャンプした際に最後の行ではなく*ヘッダー*行に着地してしまいます。

</details>

<details>
<summary>Page down / Page up</summary>

- 表示を1ページ分下（Page down）または上（Page up）にスクロールします。
- スクロール後もカーソルは画面上の同じ位置にとどまります。
- プレーンテキストでも、折り返されたセルを含むLive Previewのテーブルセル内でも動作します。

</details>

<details>
<summary>Word right / Word left</summary>

- **テキスト内:** Word rightは次の単語の末尾へ、Word leftは前の単語の先頭へ移動します — Emacs自身の`forward-word`/`backward-word`と同様です。現在の行に単語が残っていない場合は行をまたぎます。またぐ際に空行では止まりません（段落単位のモーションのみ止まりますが、このプラグインはそれを実装していません）。
- **CJK対応:** 空白・句読点だけで区切るのではなく、実際の形態素境界を使います — 中国語・日本語のひと続きのテキストは、ひとつの長い単語としてではなく、実際の単語に分割されます。
- **テーブルセル内（\*):** セルの外に出る前に、`<br>`で区切られたセル内の行をまたいで、まず現在のセル内を検索します。
- **セル内容の端にいる場合（\*):** 同じ行の隣接するセルの中で一番近い単語にジャンプします。行の端のセルからは、隣接する行の反対側の端のセルにジャンプします。またぐのはセル/行1つ分だけです。
- **プレーンテキストから到達したテーブルに入る場合（\*):** Word rightが隣接するテーブル行に着地する場合、一番左のセルの最初の単語の末尾に入ります。Word leftは一番右のセルの最後の単語の先頭に入ります — これはセル間・行間の移動が使うのと同じ着地位置です。

</details>

<details>
<summary>Kill Line</summary>

- **テーブルの外:**
  - **カーソルが行末にない場合:** カーソルから論理行の末尾までをKillします。Killされたテキストはキルキャッシュとシステムのクリップボード両方にコピーされます。
  - **カーソルが行末にある場合:** 改行をKillし、次の行と結合します。
  - **ファイルの末尾にいる場合:** 何もしません。
- **テーブルセル内（Live PreviewまたはSource Mode）:**
  - **カーソルがセル内行の末尾にない場合:** カーソルから現在のセル内行の末尾（`<br>`または`|`まで）をKillします。
  - **セル内行の末尾（`<br>`の前）にいる場合:** `<br>`タグを削除し、現在のセル内行を次の行と結合します。
  - **最後のセル内行の末尾（セルの境界）にいる場合:** 何もしません。
- **Smart join:** **Smart join**がONの場合、結合の際に次の行の本文の先頭より左にあるもの — 引用マーカー、リストマーカー、インデント、そして（**Smart home (advanced)**がONなら）見出しや脚注も — をすべて取り除きます。テーブルの外でも、テーブルセル内（`<br>`の結合）でも適用されます。
- **連続Kill:** Kill Lineを連続して行うと、キルキャッシュを置き換えるのではなく追記していきます。それ以外の編集操作（カーソル移動、入力、マウスクリック）を行うと、この蓄積はリセットされます。
- **標準のコピー/カットとの相互作用:** Ctrl+CまたはCtrl+Xを押すとキルキャッシュがクリアされ、連続Killのチェーンが途切れます。

</details>

<details>
<summary>Kill Region</summary>

- **テーブルの外:** 選択したテキストをKill（カット）し、キルキャッシュとシステムのクリップボード両方にコピーします。選択範囲は複数行にまたがることができます。
- **選択範囲が空の場合:** 何もしません。
- **テーブルセル内（Live PreviewまたはSource Mode）:**
  - **単一セル内の選択:** セル内の選択したテキストをKillします。キルキャッシュには正規化されたテキスト（`<br>` → `\n`、`\|` → `|`）が保存されます。
  - **複数行にまたがる選択:** 何もしません。
  - **セルをまたぐ選択（開始と終了が異なるセル）:** 何もしません。
  - **`<br>`を含む選択（Live Preview）:** 選択したテキストと一緒に`<br>`の区切りも削除され、前後のサブ行が結合されます。
- **Killチェーン:** Kill Regionは常に連続Killのチェーンをリセットします。Killされたテキストは追記ではなく、キルキャッシュを置き換えます。

</details>

<details>
<summary>Copy Region</summary>

- Kill Regionと同じ選択範囲の検証を行います（空の選択: 何もしない。テーブル内では単一セルの選択のみ対応 — 複数行・複数セルにまたがる選択は何もしない）が、何も削除しません — 選択範囲はそのまま残ります。
- Kill Regionと同じテーブル正規化済みのテキスト（`<br>` → `\n`、`\|` → `|`）をキルキャッシュとシステムのクリップボードにコピーします。
- **Killチェーン:** Kill Regionと同様、追記ではなく常に連続Killのチェーンをリセットします。

</details>

<details>
<summary>Yank</summary>

- **OSのクリップボードから**カーソル位置に貼り付けます。標準のCtrl+C / Ctrl+X、Kill Line、Kill Region、Copy Region、Kill word left/rightでコピーした内容にYankからアクセスできます。
- **テーブルの外:** クリップボードのテキストをそのまま挿入します。
- **テーブルセル内（Live PreviewまたはSource Mode）:** テーブル構造を壊さないよう、挿入前に改行（`\n`）は`<br>`に変換され、パイプ文字（`|`）は`\|`にエスケープされます。
- **クリップボードが空の場合:** 何もしません。

</details>

<details>
<summary>Delete Char</summary>

- **テキスト内:** カーソル位置の文字を削除します（前方削除）。
- **テーブルセル内（Live Preview）:**
  - **セルの内容の中:** 1文字を前方削除します。
  - **セル内行の末尾以外（`<br>`の前）にいる場合:** `<br>`タグを削除し、現在のサブ行を次と結合します。
  - **最後のセル内行の末尾（セルの境界）にいる場合:** 何もしません。
- **テーブルセル内（ソースモード）:** HTMLタグを意識せずに1文字を前方削除します。セル内容の境界（末尾の空白と`|`の手前）では何もしません。

</details>

<details>
<summary>Undo / Redo</summary>

- Obsidian自身のUndo/Redo履歴に対する薄いラッパーです — Undo/Redoはドキュメント全体の編集履歴に対して動作するため、特定のセルや単語に対するテーブル対応・CJK対応のロジックは関与しません。
- **なぜこれらがコマンドとして存在するのか:** ObsidianのCtrl+Z / Ctrl+Shift+Zはそれ自体動作しますが、割り当て可能なCommandに紐づいていません — これらはCodeMirror内部のキーマップに由来し、ObsidianのHotkeys設定やコマンドパレットからは見えません。これらのコマンドは、このプラグインの他のすべてのコマンドと同じように、Undo/Redoを好きなキーに割り当て可能にします。

</details>

<details>
<summary>Kill Word Left / Kill Word Right</summary>

- **テキスト内:** Kill word rightはカーソルから次の単語の末尾までを、Kill word leftはカーソルから前の単語の先頭までを削除します。行境界は自由にまたぎます — プレーンテキストのドキュメントには止まるべき構造的な境界がないためです — ただし、テーブル行だけはその手前で止まり、中には踏み込みません。
- **テーブルセル内（Live PreviewまたはSource Mode）:** セル内の複数の`<br>`区切りの行は、プレーンテキストの行と同様、ひと続きのテキストとして扱われます — Killはそれらを自由にまたぎ、途中の`<br>`も一緒に削除します。**セル自体が本当の境界です:** 別のセル（や行）は別のコンテンツなので、現在のセル内に単語が残っていない時点でKillは何もせず止まり、次のセルには踏み込みません。
- **Killチェーン:** Kill Lineと同じ連続Killのチェーンに参加します — Kill wordを繰り返し押す（またはKill Lineと混在させる）と、1つのキルキャッシュのエントリに蓄積されます。Kill word rightはキャッシュの末尾に追記し、Kill word leftは先頭に追加します。そのため、蓄積されたテキストはバッファ内に現れた順序のまま保たれます。

</details>

<details>
<summary>Uppercase word / Lowercase word / Capitalize word</summary>

- **選択範囲がある場合:** 選択したテキストを変換します。Uppercase/Lowercaseは1文字ごとに適用され、Capitalizeは単語ごとに適用されます（各単語の先頭文字を大文字に、残りを小文字にします）。単語間の空白や句読点はそのまま残ります。この選択範囲の扱いは、現在のEmacs自身の`upcase-dwim`/`downcase-dwim`/`capitalize-dwim`（現行Emacsの実際の`M-u`/`M-l`/`M-c`のデフォルト）と一致します — リージョンをまったく見ないクラシックな`upcase-word`/`downcase-word`/`capitalize-word`とは異なります。
- **選択範囲がない場合:** カーソルがどの文字の上にあるかにかかわらず、カーソル位置の単語全体を変換します — これは、選択がない場合にカーソル位置から単語末尾までしか変換しないクラシック版・dwim版のどちらとも異なります。
- **テーブル対応:** 現在のセルに単語が残っていない場合、Word rightと同じ方法でセル・行の境界をまたぎます。プレーンテキストから到達したテーブルに入る場合も同様です。
- **CJK対応:** Word right/leftやKill wordと同じ単語境界の判定を使うため、全角・半角混在のテキストも正しく処理されます。

</details>

<details>
<summary>Transpose Chars</summary>

- **テキスト内:** カーソルの前後2文字を入れ替え、カーソルをその後ろに移動します — 繰り返し押すと、1文字を右方向へ引きずっていくように動きます。実際のEmacsの`transpose-chars`と一致する挙動です。
- **行・セル内行・セルの末尾にいる場合:** 何もしない代わりに、その位置の直前の2文字を入れ替え、カーソルはそこにとどまります — これも実際のEmacsと一致する挙動で、行・セルの末尾でこのコマンドを繰り返すと便利な理由でもあります（最後の2文字を前後に入れ替え続けることになります）。
- **テーブル対応:** セルと`<br>`の境界は完全な壁になっています — Word right/leftや大文字小文字変換とは異なり、このコマンドは隣接するセルや行には決して踏み込みません。任意の隣接文字を入れ替えると、`|`や`<br>`タグの一部が実際のコンテンツと入れ替わってしまう可能性があるためです。
- **Unicodeセーフ:** 文字境界の計算には、CodeMirror自身の`transposeChars`が内部で使っているのと同じ書記素クラスタ対応のプリミティブを使用しているため、絵文字や珍しいCJK表意文字などのマルチバイト文字も、壊れることなくひとつの単位として入れ替えられます。

</details>

<details>
<summary>Select all</summary>

- **テーブルの外:** ドキュメント全体を選択します。Obsidianネイティブの Select all と同じです。
- **テーブルセル内:** ドキュメント全体ではなく、現在のセルの内容のみを選択します — Live PreviewにおけるObsidianネイティブのSelect all自体の挙動と一致します。
- **このコマンドが存在する理由:** Windowsでは、Hotkey settingsが推奨するCtrl+A → HOMEの割り当てにより、OSレベルのSelect allショートカットが組み込みの代替なしに上書きされてしまいます（[既知の制限 → ショートカットの競合](/macos-emacs-style/limitations)を参照）。このコマンドはその代替を提供します — コマンドパレットから実行するか、独自のホットキーを割り当ててください。

</details>

<details>
<summary>Recenter-top-bottom</summary>

- 押すたびに、カーソルが画面の**中央**・**上端**・**下端**のいずれかに来るように、スクロール位置を切り替えます。
- それ以外の操作（入力、カーソル移動、マウスクリック）を行うと、中央に戻ります。
- カーソルの位置自体は変わりません。
- カーソルの位置がプレーンテキストでもテーブルセル内でも、同じように動作します。

</details>

<details>
<summary>Recenter</summary>

- カーソルのある行が画面の垂直方向の中央に来るようにスクロールします。カーソルの位置自体は変わりません。
- カーソルの位置がプレーンテキストでもテーブルセル内でも、同じように動作します。

</details>

<details>
<summary>Move to cell left / right / above / below</summary>

- 指定した方向の隣接セルへ直接ジャンプし、そのセルの本文の先頭に着地します — 選択範囲は作られません。
- **左/右:** Obsidian組み込みの`Tab`/`Shift-Tab`によるセル移動（行の左右端で次/前の行に回り込み、テーブルが尽きると新しい行を挿入し、移動先セルの内容全体を選択する）とは異なり、Move to cell left/rightは常に現在の行の中にとどまります。
- **テーブルの端にいる場合**（左右移動なら一番左/右のセル、上下移動なら最初/最後の行）: 回り込んだりテーブルを抜けたりせず、何もしません。
- **テーブルセルの外では何もしません。**

</details>

<details>
<summary>Exit table above / below</summary>

- カーソルをテーブルから完全に外へ移動し、すぐ上の行（Exit table above）またはすぐ下の行（Exit table below）に着地させます — ドキュメント全体の本当の先頭/末尾にジャンプするCursor TOP/BOTTOMとは異なり、このテーブルだけを通り過ぎます。
- このプラグインの他のテーブル隣接の着地と同じ、Smart Home対応の位置決めを使用します。
- **テーブルセルの外では何もしません。**
- **テーブルがドキュメントの最終行まで続いている場合（Exit table below）:** 空行を追加してそこに着地します。Cursor DOWN自身のファイル末尾での挙動と一致します。
- **テーブルがドキュメントの最初の行から始まっている場合（Exit table above）:** 抜け出す先の行が存在しないため、何もしない代わりに、テーブルの一番上の行・一番左のセル（Smart Home調整済み）に着地します — 実際に到達可能な最も手前の位置で、常にドキュメントの本当の最初の行に到達しようとするCursor TOP自身の意図と一致します。

</details>
