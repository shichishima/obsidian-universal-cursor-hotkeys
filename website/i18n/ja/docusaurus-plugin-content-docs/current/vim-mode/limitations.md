# Vim mode — 制限事項

## テーブルをまたぐ移動

- **`w` / `b` / `e` の回数指定はセル・行の境界をまたぐと止まります:** `5w` のように回数を付けても、セルや行の境界をまたいだ時点で残りカウントが無効になります。
- **`gj` / `gk` の回数指定は行をまたぐと途中で止まります:** 同様に `5gj` のような回数指定も、1つのセルの中で複数の表示行を移動する分には正しく動きますが、行の境界をまたいだりテーブルに出入りした時点で残りカウントが無効になります。
- **回数付きの `$` はテーブルの行をまたぎません:** `3$` は、テーブルの外のように数行下の行末まで移動せず、現在のセルの中にとどまります。
- **プレーンテキストからテーブルに入ると常に左端のセルに入ります:** `j` / `k` / `gj` / `gk` でテーブルのすぐ上(または下)のプレーンテキストの行からテーブルに侵入すると、常にその行の左端のセルに入ります。Live Previewのテーブルはフォーカスされていない行について外側のエディタに文字ごとの位置情報を渡さないため、どのセルに入るべきかを判断できないためです。左端セルの範囲内で極力カーソル横位置を維持するように努めますが、2番目以降のセルに入ることはありません。(最大限右に行っても左端セルの末尾になります) テーブルに入る前のカーソル横位置は記憶したまま、その後の上下移動時でもカーソル横位置は維持されます。

## 設定・ほかのプラグインとの関係

- **設定トグルをONにすると、同じキーに自分で設定した内容が上書きされます:** これらのキーをすでにカスタマイズしている場合、そのトグルがONの間はカスタマイズが上書きされます。
- **リーダーキーが `Space` の間は `Space` 単体の元の動作が使えなくなります:** Table structure または Table navigation がONの間、`Space` 単体の元の動作(右に移動)は使えません。トグルをOFFにしても元には戻らず、Obsidianを再起動するまでの間、Normalモードで `Space` を押すと空白が入力されてしまいます。再起動すると元に戻ります。リーダーキーを `\` にすると影響はありません。詳しくは [設定](/vim-mode/settings) を参照してください。
- **Vimのテーブルセル内の挙動を独自に置き換えるプラグインとの併用は想定していません:** このプラグインはObsidian標準のVim modeを対象にしています。

## このプラグイン以外が原因のもの

- **IME(日本語入力)がオンの時にVimのキー入力が誤認識されることがあります:** 日本語入力モードが有効な状態では、Vimのモーションキー(主に `g`、`j`、`k`)を1回押しただけでも連続入力と誤認識されることがあります。たとえば、`g` を1回押しただけで `gg` として扱われたり、`j` / `k` が1行ではなく2行分移動したりします。これはObsidianが内部で使っているVimエンジン(`codemirror-vim`)の既知の問題で([issue #178](https://github.com/replit/codemirror-vim/issues/178))、このプラグインを完全に無効にした状態のObsidian標準のVim modeでも同じように再現します。**回避策:** Vimのモーションを使う前に英数入力モードに切り替えてください。
