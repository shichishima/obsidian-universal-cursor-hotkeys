# Vim mode — 既知の制限

- **CJK入力ソースがVim自身のキー処理を狂わせることがある — このプラグインが原因ではありません:** CJK（例: ローマ字入力の日本語）入力ソースが有効な状態では、Vimモーションキー（多くは`g`、`j`、`k`）を1回押しただけでも、まれに誤認識されることがあります — 例えば`g`を1回押しただけで`gg`のように扱われたり、`j`/`k`が1行ではなく2行分移動してしまったりします。これはObsidianが内部で使っている`codemirror-vim`エンジン側の既知の問題で（[issue #178](https://github.com/replit/codemirror-vim/issues/178)）、このプラグインを完全に無効化したバニラのObsidian Vimモードでもまったく同じように再現します。**回避策:** Vimモーションを使う前にASCII/半角英数の入力ソースに切り替えてください。
- **`w`/`b`/`e`は1回のカウントにつき1つのセル/行境界しかまたげません:** `5w`のようなカウント指定は、2つ以上のセル・行境界をまたぐ必要がある場合、完全には正確になりません。
- **`gj`/`gk`は境界をまたぐカウント接頭辞に対応していません:** `5gj`のようなカウントは、1つのセル内で複数の表示行を移動する分には正しく処理されますが、行境界をまたいだりテーブルに出入りしたりする必要が生じると、その最初の境界をまたいだ時点でカウントの消費が止まります。
- **プレーンテキストからテーブルに入ると常に一番左のセルに入ります:** `gj`/`gk`でプレーンテキストの行から隣接するテーブル行へ移動すると、常にその行の一番左のセルに入ります — Obsidian のLive Previewテーブルウィジェットは、フォーカスされていないテーブル行について、外側のエディタに文字単位の位置情報を一切提供しないため、着地する前にどの列に対応するセルかを判断する方法がありません。そのセル*内*の列位置は、テーブル内の行間移動と同様に保持されます。
- **カウント付きの`$`はテーブル行をまたぎません:** `3$`は、テーブルの外での本来のvimの挙動のようにさらに下の行末に到達するのではなく、現在のテーブルセル内にとどまります。
- **Obsidian組み込みのVimモードに固有の注意点:** Vimのテーブルセル内の挙動を独自に置き換えたり管理したりする別のプラグインと併用することは想定していません。
- **トグルをONにすると自分のバインドが上書きされます:** これらのキーのいずれかをすでに自分でカスタマイズしている場合、そのトグルがONの間はそのカスタマイズが上書きされます。
