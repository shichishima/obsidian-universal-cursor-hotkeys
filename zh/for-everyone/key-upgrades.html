For everyone — 按键升级

本页说明启用本插件后，各个按键的行为会发生怎样的变化。

行为升级的实质，是将插件命令分配给快捷键。由于部分按键无法在 Obsidian 的快捷键设置页面中设置，因此需要使用本插件设置页面中的开关。快捷键的分配状态确认与取消分配，同样可以在快捷键设置页面中进行。

基础操作升级​

如需查看详情，请点击对应命令列中的链接。

键
（macOS）		键
（Windows）		对应命令行为概述
↑↑UP支持表格
跨越表格行移动时，现在会保持光标的水平位置（列字符位置）。
此前跨越表格行时，光标总是会移动到行首。
↓↓DOWN支持表格
与 ↑ 相同，跨越表格行时会保持光标位置。
此前跨越行时，光标总是会移动到行首。
Home
（fn + ←）		HomeHOMESmart home
光标将按照显示行左端 → （跳过行首 Markdown 标记后的）正文文本开头 → 行首的顺序移动。
这与标准的 Home 键行为相同，但开启 Smart home (advanced) 后，原本不会执行该行为的标题行（#）、脚注行（[^1]:）、标注（> [!type]），也会在第 2 步移动到正文文本开头。
关闭 Smart home (standard) 后将不再考虑行首的 Markdown 标记，关闭 Visual line movement 后将不再移动到显示行左端。

支持表格
在表格中，于单元格开头按下 Home 会移动到左侧单元格的末尾。
此前会停留在单元格开头。

此外，当 Cross-row navigation 开启时，会从最左侧单元格开头移动到上一行最右侧单元格的末尾；关闭时则停留在最左侧单元格开头。
End
（fn + →）		EndEND支持表格
在单元格末尾按下 End 会移动到右侧单元格的开头。
此前会停留在单元格末尾。

此外，当 Cross-row navigation 开启时，会从最右侧单元格末尾移动到下一行最左侧单元格的开头；关闭时则停留在最右侧单元格末尾。
command + ↑Ctrl + HomeTOP支持表格
将光标移动到笔记开头。若笔记开头是表格，则会移动到表头行的开头。
此前若开头是表格，会移动到表格的最后一行。
command + ↓Ctrl + EndBOTTOM支持表格
将光标移动到笔记末尾。若笔记末尾是表格，则会移动到最底部一行的末尾。
此前若笔记末尾是表格，会移动到表头行的开头。
Page Up
（fn + ↑）		Page UpPage up支持表格
滚动页面时，光标会保持在屏幕上的同一位置，即使滚动后的位置落在表格内部，也能正确落位。
此前即便本应落在表格内部，光标也一定会移动到表格外。
Page Down
（fn + ↓）		Page DownPage down支持表格
与 Page Up 相同。

单词操作升级​

如需查看详情，请点击对应命令列中的链接。

键
（macOS）		键
（Windows）		对应命令功能概述
option + ←Ctrl + ←Word left支持中文
按中文/英文单词为单位向左移动。（中文基于词典进行分词）
此前，连续的汉字会被视为一个不可分割的单词整体。
option + →Ctrl + →Word right支持中文
同样按单词为单位向右移动。
option + ⌫Ctrl + BackspaceKill word left支持中文
按中文/英文单词为单位删除左侧的单词，并存入剪贴板。连续删除的内容会作为一整段文本存入剪贴板。（Emacs 风格的行为：可以将连续删除的多个单词通过一次粘贴整体贴回）
此前无法识别中文分词，且删除内容也不会存入剪贴板。
option + ⌦
（option + fn + ⌫）		Ctrl + DeleteKill word right支持中文
同样会按单词为单位删除右侧的单词，并存入剪贴板。
