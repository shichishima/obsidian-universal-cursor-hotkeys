macOS (Emacs) style — 設定

Obsidian の 設定 → コミュニティプラグイン Universal Cursor Hotkeys を選択 → 上部タブ macOS (Emacs) style を開きます。

設定画面は大きく「Hotkey settings (ホットキー設定)」と「Behavior options (挙動オプション)」で構成されています。

通常、プラグインのホットキー割り当ては Obsidian 標準のホットキー設定画面で行いますが、このプラグインではプラグイン設定画面の中でホットキー割り当て状態の確認と推奨設定の一括割り当てが行えます。

Hotkey settings (ホットキー設定)​

ここには 5 つのコマンドグループ (→解説) と「Displaced commands」(→解説) の計 6 つのブロックがあります。

Apply recommended ボタン​

コマンドグループ Cursor movement / Editing / Other hotkeys の見出しの右側に 3 つの Apply recommended ボタンがあります。これを押すとそのコマンドグループの推奨ホットキーを一括で割り当てます。

インストール直後の Obsidian であればそのまま 3 つの Apply recommended を押して構いません。macOS では初期状態でのホットキー競合はありません。Windows では推奨ホットキーと重なる既定のホットキー (Ctrl + P のコマンドパレットなど) が Displaced commands に送られますが、これらはすべて Restore で元に戻せます。(→Displaced commands 解説)

すでにホットキーを自分でカスタマイズしている場合は、他のホットキーが残るコマンド (🔵Used など) から外れたホットキーは Displaced commands に載らず Restore で戻せません。気になる場合は押す前に各行の Status を確認してください。(→Status 解説)

一括割り当ての対象は、そのコマンドグループのうちホットキーがまだ 1 つも割り当てられていないコマンドです (→例外あり)。すでに割り当てられているコマンド (✅Set、🟢Custom) と、推奨ホットキーがないコマンド (—) には影響しません。

推奨ホットキーを別のコマンドが使用中の場合 (🔵Used、🟡Used、推奨ホットキーが別の複数のコマンドに割り当てられている 🔴Conflict) は、それらのコマンドから推奨ホットキーを外して、代わりにこちらのコマンドに推奨ホットキーを割り当てます。ホットキーが 1 つも残らなくなったコマンドは Displaced commands に送られます。

例外： UP / DOWN / HOME / END の 4 つのコマンドでは「For everyone」が割り当てる素のキー (↑、↓、Home、End) を Status の判定で割り当てとして数えません。素のキーだけが割り当てられている場合も推奨ホットキーが未割り当ての状態として扱い、Set / Override ボタンが出ます。

理由： これらのコマンドは「UP は ↑ と Ctrl + P」「HOME は Home と Ctrl + A」のように、素のキーと推奨ホットキーの両方を割り当てて使うことを想定しています。もし素のキーを割り当てとして数えると「For everyone」を先に ON にした場合にこれらのコマンドが「割り当て済み (🟢Custom)」と判定され、こちら側の Apply recommended や Set / Override が適用できず、推奨ホットキーの追加割り当てができなくなってしまうためです。

Displaced commands (退避されたコマンド)​

推奨ホットキーの適用によって、割り当てられていた唯一のホットキーを失ったコマンドの一覧です。各項目には Obsidian 標準のホットキー設定画面から再割り当てするための Assign ボタンと、推奨ホットキーの割り当てを取り消して元のコマンドにキーを戻す Restore ボタンがあります。

項目説明
Command推奨ホットキーの適用によりホットキーを失ったコマンドの名前です。クリックするとコマンド名で絞り込んだ Obsidian 標準のホットキー設定画面が開きます。
Assign
ボタン		上と同じくホットキー設定画面を開きます。新しいホットキーを割り当て直すために使います。
Hotkey推奨ホットキーの適用により失われたホットキーです。クリックするとキーで絞り込んだ Obsidian 標準のホットキー設定画面が開きます。
Displaced byCommand 欄のコマンドが「Displaced commands」に送られた理由となった、このプラグインのコマンド名です。クリックするとコマンド名で絞り込んだ Obsidian 標準のホットキー設定画面が開きます。
元々「Command のコマンド → Hotkey キー」だったところを、
「Displaced by のコマンド → Hotkey キー」
「Command のコマンド → 割り当て解除」
のように Displaced by のコマンドが Hotkey を奪い取った格好です。
Restore
ボタン		現状「Displaced by のコマンド → Hotkey キー」ですが、これを
「Command のコマンド → Hotkey キー」
「Displaced by のコマンド → 割り当て解除」
として、Hotkey が奪われる前の元の状態に戻します。

この Restore ボタンにより、Apply recommended による一括割り当ての後でも比較的安全に元のホットキー状態を復元できます。

Assign ボタンや Restore ボタン、あるいは標準のホットキー設定画面によって Command 欄のコマンドにホットキーが割り当てられると、この表からは消えます。「なにかしらのホットキーによって当該コマンドが起動できるならば問題ない」という考え方によるもので、「ホットキーを割り当てて表から消すべき」という意味ではありません。

マウス操作で実行可能であったり、利用頻度が低ければコマンドパレットからの実行で十分であるものについては Displaced commands に残ったままにしておいても良いでしょう。

Behavior options (挙動オプション)​

各種挙動を調整するトグルボタンです。

同じ名称の設定項目は「For everyone」「Vim mode」「macOS (Emacs) style」で連動していて、一方で ON (または OFF) にすると他方でも連動して ON (または OFF) になります。

設定デフォルト説明
Smart home (standard)ONON: HOME コマンドが先頭の Markdown 記法 (リスト、番号付きリスト、チェックボックス、インデント、引用) の手前、本文テキストの先頭に移動します。Windows の Home / macOS の command + ← と同様の挙動です。

OFF: HOME コマンドは Markdown 記法を考慮せず、行の先頭に直接移動します。macOS / Emacs の Ctrl + A と同様の挙動です。
Smart home (advanced)ONON: Smart home (standard) の挙動に加えて、見出し (#)、脚注 ([^1]:)、コールアウトの種類マーカー ([!type]) も追加で考慮します。Smart home (standard) が ON の場合のみ ON にできます。

OFF: 見出し行・脚注・コールアウトを考慮しません。(素の Home と同等に動作します)
Smart joinOFFON: Kill line コマンドによる行の結合において、次の行の先頭の Markdown を削除します。
Smart home (standard) が ON である必要があります。
引用マーカー・リストマーカー・インデントを削除するほか、Smart home (advanced) が ON の場合には見出しや脚注も削除します。

OFF: 次の行をそのまま結合します。
Visual line movementONON: 折り返しのある長い行で HOME / END を実行した際、1 段階目は表示行の先頭 / 末尾に移動します。

OFF: 折り返し行であっても HOME / END は表示行を考慮しません。HOME は行の先頭 (Smart home 設定により、論理行の先頭または本文テキストの先頭)、END は論理行の末尾に移動します。
Cross-row navigationONテーブル内での LEFT / RIGHT / HOME / END の挙動を調整します。

ON: 左端セルの先頭で LEFT / HOME を実行すると、上の行の右端セル末尾に移動します。同様に、右端セル末尾で RIGHT / END を実行すると下の行の左端セル先頭に移動します。
行がない場合にはテーブルの外に脱出します。
(素のキー ← / → の挙動相当です)

OFF: LEFT / RIGHT / HOME / END でテーブル行移動せず、左端セル先頭または右端セル末尾で停止します。
